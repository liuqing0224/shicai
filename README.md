# 飞书简历自动评估

一个完全独立运行的本地招聘工作台：从飞书招聘只读采集候选人简历，按职位 JD 自动完成简历结构化、匹配评估和质量复核，再由招聘人员做最终决策。

## Agent 分工

| Agent | 输入 | 输出 | 边界 |
| --- | --- | --- | --- |
| 采集 Agent | 飞书招聘待评估列表 | 原始简历、候选人来源 | 只读飞书，不移动阶段、不写评价 |
| JD 岗位画像 Agent | 职位 JD | 五维岗位画像、必备项、加分项和核验标准 | 不添加 JD 未表达的硬门槛 |
| 结构化 Agent | 原始简历文本 | 标准化候选人档案 | 不做录用判断 |
| 评估 Agent | 标准化档案、岗位画像 | 逐维分数、逐项证据、风险、面试问题 | 缺少证据标为未知，不臆造事实 |
| 复核 Agent | 原始材料、评估报告 | 通过或退回、修订报告 | 检查证据一致性和评分计算 |
| 面试设计 Agent | 岗位画像、简历证据、复核报告 | 面试策略、必问/备选题、追问、案例题和评分卡 | 围绕岗位要求验证，不把风险提示当作事实 |

岗位画像按硬技能、相关经验、职责契合、硬性门槛、技术方向五个一级维度组织，并在维度下保留细粒度核验项。后端调度器按 `parse -> evaluate -> review -> interview` 串行执行每位候选人的流水线，由程序统一重算加权总分。面试设计按“岗位重要性 x 证据不确定性 x 误判成本”确定优先级，输出 8 个必问及少量备选问题，并附触发式追问、案例题和 1-4 分行为锚点评分卡。AI 的“建议通过 / 建议待定 / 建议淘汰”与人工的 `通过 / 待定 / 淘汰` 状态严格分离。

## 启动

要求 Node.js 20+。首次运行：

```bash
npm install
cp .env.example .env
npm run dev
```

- 工作台：http://127.0.0.1:5283
- API：http://127.0.0.1:8897
- 本地数据：`.data/app.db`

默认 `AGENT_PROVIDER=mock`，无需模型即可完整演示。改为 `codex` 后，调度器会按阶段分别调用本机 Codex CLI，并在每个阶段加载对应的 `agents/*/AGENTS.md`，阶段输入输出均写入本地任务记录。

## 使用流程

1. 在“职位与 JD”中创建职位，职位名称与飞书招聘中的名称保持完全一致。JD 可直接粘贴正文，也可填写当前账号有权读取的飞书文档链接；系统会通过 `lark-cli` 自动解析并生成岗位画像。
2. 在职位卡中启动飞书采集；采集目标固定为飞书招聘“简历评估 → 待评估”。
3. 首次采集会打开独立 Chromium 窗口，需要扫码登录；后续复用本项目 `.data/feishu-profile` 登录态。
4. 采集器仅获取该职位的待评估候选人，导入后自动派发结构化、评估、复核和面试设计四个阶段。
5. 从职位卡点击“查看候选人”，列表默认按匹配度从高到低排序；在详情中查看逐项证据、差距、风险、AI 建议和结构化面试指南，再标记人工最终状态。

也可以手动运行采集器：

```bash
npm run collect -- \
  --position-id <本系统职位ID> \
  --job-name "<飞书中的准确职位名>" \
  --tenant https://your-company.feishu.cn \
  --api-base http://127.0.0.1:8897 \
  --import
```

## 安全与隐私

- 飞书侧严格只读，不自动移动候选人阶段或填写评价。
- 登录态仅保存在本项目 `.data/feishu-profile`，不读取或打印 Cookie。
- 简历和报告只写入本地 SQLite 与任务目录，均被 Git 忽略。
- 发送给分析 Agent 前自动隐藏邮箱和中国大陆手机号。
- 自动评分只用于辅助筛选；最终录用决策必须由招聘人员完成。

更多说明见 `docs/`。
